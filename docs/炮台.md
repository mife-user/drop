# 炮台：花钱买一座，自己找地方放，水喷完自己消失

想做一个「**花邮币买一台会自动喷水的机器，自己挑地方插在地里，它会一直浇到水箱见底**」的玩意儿，看这一篇。
菜单怎么瞄、怎么关、怎么锁人在 `docs/交互台.md`；升级的价格和等级怎么算在 `docs/升级台.md`。
**这里只讲炮台这一套独有的东西**：四行菜单卖什么、买完为什么先拿在手上、抛物线怎么配、什么时候消失、
放下之后怎么按 P 拆掉。

涉及四个文件：

| 是什么 | 场景 | 脚本 |
|---|---|---|
| 商店（摆在世界里那台） | `scenes/炮台.tscn` | `scripts/水枪/炮台.gd` |
| 买到的炮台（运行时才生成） | `scenes/炮台发射器.tscn` | `scripts/水枪/炮台发射器.gd` |

---

## 一、商店卖四行

| 第几行 | 卖什么 | 数值存在哪 | 每级怎么变 |
|---|---|---|---|
| 0 | 购买炮台 | 商店自己的 `buy_cost`（+ 每买一座涨 `buy_cost_step`） | 花邮币，生成一座新的 |
| 1 | 发射间隔 | 商店的 `fire_interval`（秒/发） | **往小里升**：每级减 `interval_step`，最低到 `interval_min` |
| 2 | 水块大小 | 商店的 `blob_size`（米） | 每级加 `size_step`，上限 `size_max` |
| 3 | 水量容量 | 商店的 `capacity`（立方米） | 每级加 `cap_step`，上限 `cap_max` |

「发射间隔」是唯一**往小里升**的一项，所以判断到没到顶看的是下限：

```gdscript
func _is_maxed(index: int) -> bool:
	match index:
		Upgrade.INTERVAL:
			return fire_interval <= interval_min + 0.0001
		...
```

> 和别处一样，浮点数加几次不一定正好等于极限值，所以用**和它自己的 step 同量级**的小量兜底，别写 `==`。
> 界面上的写法也顺着来：「发射间隔 0.50 → 0.40 秒/发」——间隔越小喷得越密，
> 玩家看一眼就懂；想改成「2.0 → 2.5 发/秒」也行，但那就得在脚本里换算，别只改格式串。

**升级只影响之后买的炮台。** 商店自己就是那套「出厂规格」的唯一存放处，买的时候盖到新炮台上：

```gdscript
turret.fire_interval = fire_interval   # 买下来的这一座按"现在菜单上写的数"配置
turret.blob_size = blob_size
turret.capacity = capacity
```

这和「水块容器」给每团水盖合并规则是同一个写法。**已经摆在场上的那座不会被回头改** ——
不然菜单上的数字和场上那台就对不上了（两个真相）；而且 `capacity` 更是改不得：水枪类的
`_ready()` 会拿它当满水开局，入树之后再改，读数就永远对不上实际水量。

## 二、买一座炮台，中间发生了五件事

```gdscript
func _buy() -> void:
	if not _can_buy():            # 场上够多了 / 手上还拿着一座
		show_message(text_busy, false)
		return
	if is_instance_valid(wallet) and not wallet.spend(_buy_cost()):
		show_message(text_blocked, false)
		return
	var turret: WaterTurret = _spawn_turret()      # 造出来、按出厂规格配好、挂在商店下面
	if turret == null:
		wallet.add_money(_buy_cost())              # 造不出来就把钱退回去
		return
	_buy_level += 1
	turret.begin_carry()      # 1) 先拿在手上
	close_menu()              # 2) 再收菜单（顺序不能反，见下）
```

1. **扣钱、造炮台**：先填好 `field` / `fire_interval` / `blob_size` / `capacity` **再入树**
   （理由见上一节）。炮台挂成商店的子节点，在远程场景树里叫「炮台1」。
2. **拿在手上**（`begin_carry()`）：从这一刻起它**不喷水、不挡人、半透明**，悬在视线前方跟着你走。
3. **收菜单**：玩家解锁，可以去挑地方了。
4. **滚轮调朝向、左键放下**（`place()`）：放置预览时，上下滚轮绕炮台中心的竖直轴向两个方向旋转，默认每格 15°；左键按到投影那个点上，保留选定朝向并开始自动喷水。**放下后不再响应滚轮旋转。**
5. **水喷完自己消失**：`_physics_process()` 里发现 `has_water()` 变 false 就收缩消失。

### 携带期间的两条"封锁"，都是为了让左键只干一件事

放炮台用的是左键，而左键在这个项目里本来就兼着两件事（开火、菜单确认），所以携带期间必须把它们按住：

- **玩家的水枪被关掉**：`gun.can_fire = false`。水枪是每帧**轮询**按键的（不是事件），
  所以"把事件吃掉"拦不住它，只能关开关。收菜单和携带都要关水枪，两件事会打架，所以：
  **先 `begin_carry()` 再 `close_menu()`** —— 这样 `on_menu_closed()` 一看"还在携带"就不还水枪了；
  炮台落地时才由 `_on_turret_placed()` 还回去。
- **全场台座不弹菜单**：炮台把自己挂进 `interact_blocked` 组，`交互台.gd` 按 E 前会看一眼这个组。
  不拦的话，玩家举个炮台去别的商店按 E，菜单一开，点选项花的钱和"放下炮台"就是同一下左键了。

> 这两个开关都写了**兜底**：炮台万一不是正常落地（被别处删了），`tree_exited` 那条路也会把水枪还回来。

## 三、放下之前，投影是怎么来的

携带中每帧（`_update_carry()`）：

1. 位置 = 摄像机 + 视线方向 × `hold_distance`，再往下 `hold_drop` 米 —— **悬在眼前，不是你手上**，
   所以站着不动只转头，就能把它挪到脚边、屋顶上、水池对岸。
2. 朝向只取视线的**水平那一段**（`atan2(-flat.x, -flat.z)`，和 `player.gd` 的 `look_lock` 同一个公式）：
   再叠加滚轮累积的偏转角；移动或转动视角时会保留这个偏转。抬头低头时炮台不会跟着翻，永远立着。
   滚轮只改变朝向，不移动炮台中心；**炮台的前方 = 它自己节点的 -Z。**
3. 从它正下方打一条向下的射线（`ground_probe` 米，`ground_mask` 默认第 1 层世界），
   打到哪儿，投影圈就摆到哪儿。
4. 落点是否合法：**再拿一个小球探一下 `forbid_mask`（默认第 4 层 = 吸水区）**，
   压着水池/木碗就不许放。用小球而不是打点，是因为站在池边往下看时落点常常正好在沿上。

合法 = 投影蓝色、准星下面写「滚轮旋转，左键放置炮台」；不合法 = 投影变红、写「这里不能放」、
**左键点了什么都不发生**（但这一下左键仍然被吃掉，不会漏到别处去）。

> 投影圈是炮台场景里那个 `投影` 节点（一个扁平圆环），颜色在检查器里配：
> `shadow_ok_color` / `shadow_bad_color`，抬多高防闪烁是 `shadow_lift`。
> **材质在 `_ready()` 里复制了一份**（网格也复制了）—— 场景里的子资源是所有炮台共用的，
> 不复制的话「这一座变红」会把场上别的炮台一起染红，和水块复制碰撞形状是同一个道理。

## 四、它怎么开火、往哪儿浇

`scripts/水枪/炮台发射器.gd` **继承 `WaterGun`**，白拿这些：发射间隔的冷却循环、
一发水多大（`blob_size`）、整个水箱（`capacity` / `amount` / `has_water()` / `shot_volume()`）、
上方那块水量读数（`读数` Label3D）、抛物线反解。**只覆盖三处**：

| 覆盖 | 原来（水枪） | 现在（炮台） |
|---|---|---|
| `_is_firing()` | 按住左键 + 鼠标锁着 | **放下就一直想开火**（冷却会按住 `fire_interval` 限速） |
| `_launch_direction()` | 从枪口朝准星线上第 N 米反解 | 朝**自己正前方 `launch_distance` 米、再往下 `launch_drop` 米**那个点反解 |
| `_physics_process()` | 父类那套 | 开头多看一眼水箱：**见底就收缩消失** |

调落点就动这两个数：`launch_distance`（多远，默认 4 米）和 `launch_drop`（比枪口低多少，
默认 1 米 —— 调到"水正好落在地面上"为止，枪口越高这个值越大）。两个都在
`scenes/炮台发射器.tscn` 的根节点上，运行中也能改。

**水还是走主场景那个 `水块容器`**，和水枪共用 `muzzle_speed` 和 `gravity`。所以别处把
「出水速度」买上去之后，炮台的**落点不会变**（每发都按当前初速现解一次抛物线），只是弧线变平。

**`枪口` Marker 要摆在碰撞盒外面**（模型炮管尖上）。摆在盒子里的话，水一出膛就撞在自己身上散掉 ——
水团打射线只认「世界」层，它认不出"这是我自己的炮台"。

## 五、为什么"水喷完就消失"

炮台喷出去的水落在地上、被 `吸水区` 收下，而 `水量换币`（跟在钱包里，见 CLAUDE.md）是**按水量给邮币**的 ——
所以一座炮台约等于一台会自己赚钱的机器，只是它的水有限：**喷完那 10 m³ 就没了**。
「用完消失」就是它的寿命，也是这套经济里唯一的花钱去处。

按默认值算：水块 0.35 米 → 一发 0.0429 m³ → 10 m³ 大约 **233 发**；
发射间隔 1.0 秒/发 → 一座炮台能喷约 **4 分钟**。
**升级射速会让它更短命**（同样 233 发，喷得更快就结束得更快）—— 这是设计上就该如此，
不是 bug；「水量容量」那一行就是拿来对冲它的。

## 六、看着它按 P 拆掉

放下之后（携带中不算）准星对着炮台，屏幕中心下面就会出现「按 P 拆除炮台」，按 P 收缩消失。
**全程没有菜单、不锁人、不锁视角** —— 这是「一键拆除」，不是交互台那一套
（炮台脚本没法 `extends InteractStation`：它已经继承了 `WaterGun`，GDScript 是单继承）。

它走的是**和水箱喷完完全相同**的那条路（`_dry_up()`）：收缩一下再 `queue_free`。
所以「拆掉」和「喷完」的表现一模一样，只有触发源不同 —— 想改拆除动画，改 `dry_shrink_time` 就够，两条路一起变。

判定「准星对着的是不是我」是一条射线（`_is_aimed_at_me()`）：

```gdscript
var hit: Dictionary = get_world_3d().direct_space_state.intersect_ray(query)
return not hit.is_empty() and hit.get("collider") == body
```

和交互台判「准星对着的是不是我」是同一个写法。**每座炮台都在每帧问同一条射线、拿结果跟自己的
`body` 比**，所以同一时刻最多只有一座是真的「被瞄着」，不会两座都响应。
射线查「世界」层（`remove_mask` 默认 1），炮台自己的碰撞盒就在这层 —— 顺带让墙和别的炮台也能挡住：
隔着墙拆不掉，也不会拆到墙后面那座。

**收尾全归商店**：炮台是商店的子节点，`tree_exited` 一发，商店就把玩家的水枪还回来、
菜单上那行「场上已有炮台」跟着变回「购买炮台」。所以 `dismantle()` 里只有一行 `_dry_up()`，
它不认识邮币、也不认识商店。

**不退款**：拆了就是拆了，箱里剩的水白费。喷出去的水早就被吸水区收下、换成邮币了，
再按剩余水量退一笔就等于刷币 —— 这是特意不做的。真要做，得让商店在买的时候把钱包和买价
一并**盖**给炮台（就是第二节那套「盖章」写法，和 `fire_interval` 那三个一个路子）。

> 键位在 `project.godot` 的 `[input]` 里，动作名 `remove_turret`（默认 P），和 `interact` / `stats`
> 一样能在项目设置里改键。项目设置里没这个动作时脚本会退回直接认 P 键（`REMOVE_KEYCODE`），不会静默失灵。

## 七、在检查器里能配什么

**商店（`场景/水炮` 节点）**

| 分组 | 参数 | 说明 |
|---|---|---|
| 接线 | `wallet` / `field` / `gun` / `turret_scene` | 邮币账本 / 水块容器 / 玩家的水枪 / 炮台场景 |
| 出厂规格 | `fire_interval` `blob_size` `capacity` `max_turrets` | 下一座炮台的三个数值；`max_turrets` 填 0 = 不限 |
| 购买炮台这一行 | `buy_cost` `buy_cost_step` `buy_text` `buy_full_text` `buy_full_price_text` `text_busy` | 价格和话术 |
| 三条升级行 | `xxx_text_format` `xxx_text_max_format` `xxx_step` `xxx_min`/`xxx_max` `xxx_cost` `xxx_cost_step` | 见 `docs/升级台.md` 第三节 |

**炮台（`scenes/炮台发射器.tscn` 根节点）**

| 分组 | 参数 | 说明 |
|---|---|---|
| 发射 | `launch_distance` `launch_drop` `dry_shrink_time` | 落点多远 / 比枪口低多少 / 消失用多久（拆除和喷完共用这一个） |
| 携带与放置 | `hold_distance` `hold_drop` `ground_probe` `ground_mask` `forbid_radius` `forbid_mask` | 拿在哪儿、怎么找地面、哪里不许放 |
| 携带与放置 | `placement_rotation_step` | 放置预览时滚轮每格的旋转角度，默认 15°；放下后无效 |
| 携带与放置 | `preview_color` `shadow_ok_color` `shadow_bad_color` `shadow_lift` | 半透明预览和投影圈的颜色 |
| 拆除 | `removable` `remove_distance` `remove_mask` `remove_hint` | 能不能按 P 拆 / 隔多远 / 瞄准射线查哪层 / 提示那句话 |
| 携带时的话术 | `hint_carry` `hint_blocked` | 准星下面那两句话 |
| （从水枪继承） | `fire_interval` `blob_size` `capacity` `readout` `empty_color` … | 商店买的时候会**盖掉**前三个 |

## 八、坑（都想过一遍）

1. **`_ready()` 里的 `super()`** —— 炮台那边是 `WaterGun._ready()`（满水开局 + 刷读数），
   忘调就是一座空水箱、马上消失。
2. **规格要在入树前盖**，入树之后再改 `capacity` 读数就对不上了（第一节）。
3. **先 `begin_carry()` 再 `close_menu()`**，反了的话收菜单时会顺手把水枪打开（第二节）。
4. **`枪口` 要摆在碰撞盒外**，否则水一出膛就撞自己身上（第四节）。
5. **别给商店节点加缩放** —— 炮台是它的子节点，会被一起缩放。
6. **炮台是运行时生成的**，所以改它的行为参数要改 `scenes/炮台发射器.tscn` 那个场景文件
   （或者运行中在远程场景树里改），在主场景的检查器里看不到它 —— 和"水团"是同一个情况。
7. **面板现在摆了四行**（`scenes/交互模板/交互面板.tscn`）。菜单再想加第五行，得先往面板里
   再实例一个「交互选项行」，否则 `row_count()` 多出来的那行会被当作不存在。
8. **放置不能取消**。拿在手上就必须找个地方放下 —— 所以"哪里能放"的判定不能太严，
   现在只禁掉「射线打不到地面」和「压着吸水区」两种情况。
9. **「按 P 拆除炮台」那行字是「认主」的**（见 `交互准星.gd`）。炮台一没，这行字就没人擦了 ——
   场上别的台座每帧写的空字符串能顺手兜住，但那是别人帮的忙，不该指望。所以被拆 / 喷完时
   `_dry_up()` 里自己擦一次，`_exit_tree()` 里再兜一道，**这两处别删**。
   另外「有人正拿着炮台」时这一套整个让位（不弹提示、不认 P 键），免得和「左键放置炮台」抢同一行字。
10. **商店的面板摆在了机器碰撞盒的肚子里**（面板在 z=0.29，而碰撞盒前面伸到 z=0.52）。
   靠 `交互台.gd` 那道「开菜单时把实体从射线里摘掉」的保险才没出事 ——
   当时的表现是「**四行菜单只有第一行能选**」，根因是射线先撞上盒子、到不了下面几行的选中区。
   完整来龙去脉见 `docs/交互台.md` 第七节第 2 条。**新做台座时面板尽量别往盒子里塞。**

# 升级台：花钱把某个数值买上去

想做一个「**点 E 弹出菜单 → 瞄准某一行 → 左键花钱买 → 数值真的变了**」的机器，
看这一篇。菜单长什么样、怎么瞄、怎么关、怎么锁人那套流程在 `docs/交互台.md`，**这里只讲"升级"这件事本身**。

现成的两台：

| 台座 | 场景 | 脚本 | 卖什么 |
|---|---|---|---|
| 水枪升级台 | `scenes/水枪升级.tscn` | `scripts/水枪/水枪升级.gd` | 出水速度（水块容器）、水块大小（水枪） |
| 消防栓 | `scenes/消防栓.tscn` | `scripts/水枪/消防栓.gd` | 装水速度（消防栓自己）；另外长按 E 接水 |
| 炮台商店 | `scenes/炮台.tscn` | `scripts/水枪/炮台.gd` | 购买炮台（四行菜单）；详见 `docs/炮台.md` |

---

## 一、一条铁律：**数值只存一份，存在"用它的那个人"身上**

升级台**不保存任何数值**。它买的那个数，就写在**真正要用这个数的地方**：

| 升级项 | 数值存在哪 | 谁在用 |
|---|---|---|
| 出水速度 | `水块容器.muzzle_speed` | `水块.gd` 拿它当出膛初速 |
| 水块大小 | `水枪发射器.blob_size` | `水枪.gd` 拿它当一发水的大小、也拿它算耗水量 |
| 装水速度 | `消防栓.fill_speed` | `消防栓.gd` 自己按它往水枪里灌水 |

**为什么**：如果升级台另外存一份「现在几级、数值多少」，就出现了两个真相。
在检查器里手改一次、或者以后读档进来，两边立刻对不上 ——
典型表现是「买完水枪变快了，但菜单上写的还是旧值」或者反过来的。

所以规矩是：**菜单上显示的数字、买的数字、实际生效的数字，是同一个变量**。
消防栓的 `fill_speed` 既是「按住 E 时每秒灌多少」，也是菜单那一行升级的对象，改完全场立刻一致。

---

## 二、等级是怎么算的

**等级不是一个数字，是「买过几次」的计数器。** 每个台座自己拿一个 `var _xxx_level: int` 记着：

```gdscript
var _speed_level: int = 0    # 装水速度买过几次（价格按它递增；速度本身存在 fill_speed 上）
```

它**只干一件事：算价格**。

```gdscript
## 这一项现在卖多少钱：底价 + 已经买过几次 × 每次涨的价。
func _cost() -> int:
	return speed_cost + speed_cost_step * _speed_level
```

数值本身怎么涨、涨到哪为止，走另外两行：

```gdscript
fill_speed = minf(fill_speed + speed_step, speed_max)   # 加一级，夹在上限
_speed_level += 1                                        # 价格计数器 +1
```

到没到顶看的是**数值**，不是等级：

```gdscript
func _is_maxed() -> bool:
	return fill_speed >= speed_max - 0.0001
```

> **为什么要减 0.0001**：浮点数加上 0.05 若干次之后不一定正好等于上限，
> 直接写 `>= speed_max` 会出现「明明满了却显示还能买」。
> 每一项都用**和它自己的 step 同量级**的小量兜底，别写 `==`。

这样设计的好处：**价格和数值互不干扰**。在检查器里手改一次 `fill_speed` 不会把价格搞乱，
以后加了存档、或者别处也来改这个数，菜单都会如实反映。

## 三、一行升级要在检查器里配什么

每一行升级都是**一组 @export**，全部在这个台座的节点上，**不在公共件里**（面板是共用的，行文字是子类给的）。

| 参数 | 填什么 | 例（消防栓的装水速度） |
|---|---|---|
| `xxx_text_format` | 左边那句，**两个 %f**：现在多少 / 买完多少 | `装水速度  %.2f → %.2f m³/秒` |
| `xxx_text_max_format` | 到顶后左边那句，**一个 %f** | `装水速度  %.2f m³/秒（已满）` |
| `xxx_step` | 每级加多少 | `0.05`（立方米/秒） |
| `xxx_max` | 上限；**到了就不再涨价、也买不了** | `1.0` |
| `xxx_cost` | 第一级多少钱 | `3` |
| `xxx_cost_step` | 每买一级，下一级贵多少 | `2` |

**%f 的数位直接写在格式串里**（`.2f` 两位、`.1f` 一位），
和数值的量级对上就行 —— 装水速度用两位，水块大小用两位，出水速度用一位。

数值本身**不在这组里**（见第一节），它属于被升级的那个节点。

## 四、四行代码长什么样

一个台座卖几行，全靠这 4 个函数。面板里摆了 4 行，`row_count()` 返回几就显示几行（多的自动藏）。

```gdscript
func row_count() -> int:
	return 1

## 左边那句说明
func row_text(_index: int) -> String:
	if _is_maxed():
		return speed_text_max_format % fill_speed
	return speed_text_format % [fill_speed, minf(fill_speed + speed_step, speed_max)]

## 右边那个价格
func row_price_text(_index: int) -> String:
	return price_max_text if _is_maxed() else price_format % _cost()

## 这一行能不能买：到顶变灰、买不起标红
func row_state(_index: int) -> InteractOptionRow.State:
	if _is_maxed():
		return InteractOptionRow.State.DONE      # 灰字
	if not is_instance_valid(wallet) or not wallet.can_afford(_cost()):
		return InteractOptionRow.State.BLOCK     # 红字
	return InteractOptionRow.State.OK

## 左键点了这一行：先看到没到顶、再看钱够不够，最后才真扣钱、真改数值
func on_row_activated(_index: int) -> void:
	if not is_instance_valid(wallet):
		return
	if _is_maxed():
		show_message(text_done, false)
		return
	if not wallet.spend(_cost()):                # 钱不够时一分不扣，返回 false
		show_message(text_blocked, false)
		return
	fill_speed = minf(fill_speed + speed_step, speed_max)
	_speed_level += 1
	show_message(text_success, true)
```

**顺序不能换**：先判到顶、再判钱、最后才扣钱改数。
点完基类会自动把整块菜单重算一遍（`refresh_rows()`），子类不用自己刷。

## 五、钱

邮币账本是主场景 `界面/邮币/Money2` 上的 `CurrencyLabel`（`scripts/money.gd`），**每台自己接一次**：

```gdscript
@export var wallet: CurrencyLabel

func _ready() -> void:
	super()
	if is_instance_valid(wallet):
		wallet.money_changed.connect(_on_money_changed)

## 钱一变就重算菜单 —— 在别处花了钱，这里的价格颜色要跟着变
func _on_money_changed(_amount: int) -> void:
	refresh_rows()
```

测试用：`scenes/money.tscn` 里的「起始邮币」填多少开局就有多少。

## 六、接一台新的升级台：照着抄

1. **复制现成的**：`scenes/水枪升级.tscn` 或 `scenes/消防栓.tscn` 另存一份，改结构照着下面来。
   脚本照 `scripts/水枪/水枪升级.gd` 抄一份到 `scripts/` 下对应的子目录。
2. 场景里改成：根节点（`Node3D` + 你的脚本）→ `模型`（把你的模型实例拖进去）
   → `实体`（`StaticBody3D`，`collision_layer` **必须是 17**）→ 它下面 `CollisionShape3D`
   → `面板`（`scenes/交互模板/交互面板.tscn` 的实例）。**这五个名字里的 `实体` / `面板` 不能乱**，
   台座是按**类型**找它们的（`_resolve_refs()`），层级也要对：必须是根节点的直接子节点。
3. **碰撞盒包住模型、稍微大一圈**，否则准星打不到。层号 17 = 世界(1) + 可交互(5)，别动。
4. 根节点上填：`title_text`（菜单标题，**每台一份**）、`prompt_text`（"按 E 升级"之类）、
   `text_blocked` / `text_done` / `text_success`（弹的那几句提示）。
5. 脚本里 `extends InteractStation`，实现第一节那四个 `row_*` / `on_row_activated`。
6. 拖进主场景摆好，把这台自己的接线接上（`wallet` + 你要升级的那个节点）。**其余不用接** ——
   面板、碰撞体、主人公、准星是它自己在 `_ready` 里找的。
7. 进游戏走一遍：瞄上去出提示 → E 弹菜单 → 扫到那一行会亮 → 左键花钱 → 数值和价格立刻变。

**给已有的台加一行**：在面板里把第 2 / 3 行摆出来，`row_count()` 改大，多写一组 `@export`，
在 `row_text` / `row_price_text` / `row_state` / `on_row_activated` 里按 `index` 分叉。
**公共件一行都不用改。**

## 七、坑（都踩过）

1. **`_ready()` 里必须先 `super()`**。基类在 `_ready` 里收菜单、把行铺好、连准星；
   忘了调 = 菜单是空的、按 E 没反应。
2. **数值别在台座上再存一份**。只有 `_xxx_level` 这个价格计数器是允许存的，见第一节。
3. **升级不存档**。退出或重开场景就回到场景里填的初始值（项目里还没有存档系统），
   所以**初始值要在检查器里填成"第一级之前的样子"**，不要指望运行时的改动留下来。
4. **`text_format` 的 %f 个数要对**：`xxx_text_format` 两个、`xxx_text_max_format` 一个。
   少一个会报格式错误，菜单直接不显示。
5. **一行有多宽跟着「高亮」那条 `QuadMesh` 走**，文案太长会自动缩字号（缩到 `min_font_size` 为止）——
   字太小说明该把高亮条拉宽了，而不是去改 `min_font_size`。
6. **升级项之间会互相影响时，要想清楚**。例：水块大小买上去之后，一发水更大 ——
   而水枪的水箱是**按体积扣水**的（`blob_size³`），所以**每发耗水会跟着变多**，
   一箱能射的发数变少。这是设计上就该如此（射出去的水真的更多了），不是 bug，但调数值时要心里有数。
7. **面板里摆了 4 行**（`scenes/交互模板/交互面板.tscn`）。`row_count()` 超过摆出来的行数，
   多出来的会当作没有那一行 —— 想卖第五行，先去面板里再实例一个「交互选项行」。
